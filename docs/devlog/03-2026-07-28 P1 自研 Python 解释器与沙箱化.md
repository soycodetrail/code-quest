## P1-3 自研 Python 解释器（MiniPython）

### 为什么自研——三个方案对比

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| Pyodide (WASM) | 完整 Python | APK 增 8MB，首次加载慢 | ✗ |
| 服务端执行 | 可扩展（多语言/评测） | 依赖网络 + 维护安全沙箱 | ✗ |
| **GDScript 子集解释器** | 零依赖、跨平台一致、离线可用 | 只支持教学子集 | ✓ |

**最终架构**：双 backend，自动按平台选择
- 桌面（macOS/Windows/Linux）：优先系统 `python3`，失败回退 MiniPython
- 移动/Web：直接用 MiniPython

### 实现分层（1100 行）

```
MiniPythonInterpreter.gd
├── Lexer（词法分析）
│   ├── 每行首插 BOLO token 携带 indent 值
│   └── _bolo_to_indent: BOLO → INDENT/DEDENT
├── Parser（递归下降）
│   ├── parse_program → parse_statement
│   ├── parse_if / parse_while / parse_for / parse_def
│   └── parse_expr 优先级链：or < and < not < 比较 < +- < */%// < 一元 < ** < 后缀
└── Interpreter（AST 遍历）
    ├── globals Dictionary 做环境
    ├── _call_user_func: 函数调用栈切换保存恢复
    └── _py_str: Python 风格的值字符串化
```

### 安全保护

```gdscript
var max_steps: int = 1000000
var steps: int = 0

func _check_steps() -> void:
    steps += 1
    if steps > max_steps:
        _set_error("执行步数超限（可能死循环）")

# while 单独再加循环上限
func _exec_while(node: Dictionary) -> void:
    var safety: int = 0
    while error == "" and _truthy(_eval(node["cond"])):
        safety += 1
        if safety > 1000000:
            _set_error("while 循环次数过多")
            return
```

玩家写 `while True: ...` 不会卡死游戏。

### PythonRunner.gd 双 backend 调度

```gdscript
const MINIPY_SCRIPT := preload("res://scripts/MiniPythonInterpreter.gd")

func _ready() -> void:
    _minipy = MINIPY_SCRIPT.new()
    var platform := OS.get_name()
    if platform == "macOS" or platform == "Windows" or platform == "Linux":
        _python3_available = _detect_python3()
        _use_real_python = _python3_available
    else:
        _python3_available = false
        _use_real_python = false

func execute_code(code: String) -> void:
    if _use_real_python and _python3_available:
        var r: Dictionary = _exec_with_python3(code)
        if r["fallback"]:
            var r2: Dictionary = _exec_with_minipy(code)
            execution_finished.emit(r2["output"], r2["success"])
        else:
            execution_finished.emit(r["output"], r["success"])
    else:
        var r3: Dictionary = _exec_with_minipy(code)
        execution_finished.emit(r3["output"], r3["success"])
```

## 踩坑与修复

### 坑 1：GDScript `match()` 方法名与 `match` 语句关键字冲突

报 `Parse Error: Expected closing ")" after grouping expression`。我给 Parser 写了个辅助方法 `func match(...)`，但 GDScript 把 `match` 当 match 语句关键字。

**修复**：全部改名 `_match()`，perl 批量替换：
```bash
perl -i -pe 's/\bfunc match\b/func _match/g; s/(?<![a-zA-Z_])match\(/_match(/g' scripts/MiniPythonInterpreter.gd
```

### 坑 2：`_ = expr` 不是合法赋值

Python 习惯用 `_ = func_call()` 丢弃返回值，GDScript 不支持。

**修复**：直接调用，不接收返回值。

### 坑 3：`-> null` 不是合法返回类型

返回类型注解只能用具体类型或 `void`。

**修复**：`-> null` 改成 `-> void`。

### 坑 4：严格模式 `var x := func_call()` 推断失败

报 `Cannot infer the type of "r" variable because the value doesn't have a set type`。函数返回 Variant / 无类型 / Dictionary 时触发。

**修复**：所有 `var x := ...` 改成显式类型：
```gdscript
var r: Dictionary = _interp.execute(...)
```

### 坑 5：整数幂返回 float

`print(2 ** 10)` 输出 `1024.0`，期望 `1024`。GDScript 的 `pow()` 总返回 float。

**修复**：整数底 + 整数指数走循环乘法，负指数才退回 float。

### 坑 6：String.split 返回 typed array 导致 `_py_str` 走 GDScript 原生格式

`print("a,b,c".split(","))` 输出 `["a", "b", "c"]`（双引号 + 空格），期望 `['a', 'b', 'c']`。Godot 的 `String.split()` 返回 `PackedStringArray`，`_py_str` 只处理 Array/Dictionary。

**修复**：方法返回前转成普通 Array。

### 坑 7：`len(dict)` / `for k in dict` 不支持字典

**修复**：`BUILTIN_LEN` 加 Dictionary 分支；`_exec_for` 加 Dictionary 迭代（默认迭代 keys）。

更多 GDScript 陷阱见 [[07-GDScript 语言陷阱汇总]]。

## 经验总结

1. **跨平台沙箱化的最优解取决于使用场景**——教学闯关游戏用子集解释器最合适，避免 WASM 体积和网络依赖
2. **GDScript 严格模式下 `:=` 推断 Variant 会报错**，函数返回 Variant 必须显式类型
3. **方法名要避开关键字**（`match`、`for`、`in`、`if`）
4. **typed array 与 untyped array 行为不一致**——PackedStringArray 不被识别为 Array，跨边界要转换
5. **死循环保护是 must-have**——玩家一定会写 `while True`，1M 步上限是合理兜底
